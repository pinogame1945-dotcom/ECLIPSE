# 週次レポートの凍結テンプレートの取得と必須事前検査

2026-10-11 不具合対策。

## 事象と根本原因

過去会話で完成済みの「ECLIPSE_WEEKLY_TEMPLATE_V1.0.1.zip」「WEEKLY_GOLDEN_V1.0.pptx」は ChatGPT ライブラリ／Project ファイル一覧から名前とメタデータが検索できた。しかし**今回のレポート生成環境には元PPTXのバイト列が存在しなかった**。ライブラリ経由の `raw_file` 取得も「authorized raw-byte materialization pathなし」で拒否された。

一方、public GitHub `templates/weekly_v1` にあるのは凍結デザインの**署名・運用契約**だけで、原本PPTX自体は意図的に保存されていない。よって今回のレンダリング担当が原本を読み込めなかったこと自体は事実。

**本質的な不具合は、読み込めないことを知りながら別レイアウトで生成し、完成品として案内したこと。** この成果物はデザイン凍結準拠と扱ってはならない。

## 変更後の必須ゲート（非公開原本はGitに追加しない）

`src/eclipse_reports/weekly_template_gate.py` を追加した。全週報生成前に実ファイル `WEEKLY_GOLDEN_V1.0.pptx` またはその原本を含む `ECLIPSE_WEEKLY_TEMPLATE_V1.0.1.zip` を読み込み、GitHubデザイン凍結契約と以下を照合する。

- 標準原本PPTXの SHA-256 が `67b11361f2fa5e5187713be683c92b91069d54afe262fe972bbc76aedfceb77a` と**完全一致**。
- 19枚の元デザイン、テーマ・マスタ/レイアウトの保護パーツが凍結契約と一致。
- コピー先の原本を上書きしない（抽出は新しい別の場所に限定）。
- 元バイトをダウンロードできない、別テンプレート、SHA相違、原本ファイルがZIP内にない、ZIP破損などは**例外終了**。類似テンプレート生成／元スライドの勝手な再描画は禁止。
- ハッシュ照合は**デザイン原本の確認**であり、事実内容の確認・顧客配布可否は別のゲート。

~~~bash
# デザイン原本が読み取れる非公開の作業環境にある場合
PYTHONPATH=src python -m eclipse_reports.weekly_template_gate verify \
  --source /secure-source/ECLIPSE_WEEKLY_TEMPLATE_V1.0.1.zip

PYTHONPATH=src python -m eclipse_reports.weekly_template_gate extract \
  --source /secure-source/ECLIPSE_WEEKLY_TEMPLATE_V1.0.1.zip \
  --out /work/verified-golden.pptx
~~~

## 出所を永続的に解決する方法

1. 元テンプレートZIPを**本会話にファイルとして添付**して、今回の作業環境にバイト実体があることを確認する。名前・検索結果だけでは不足。
2. 今後の自動生成は、原本を**アクセス制御された永続ストレージ**（例：社内の非公開アーティファクト／非公開GitHub Releases／Kaggle private等、利用許可済みの保存場所）に保存し、生成ごとにSHA-256照合して取得する。ただし保存先への実際のアップロードは、実ファイルと適切な認証がある場合だけ実施する。
3. 19ページの元デザインを使い、許可された原型の複製のみでページ追加。カスタムデザインでの代用は禁止。

**このゲートだけで過去ファイルへアクセス可能になる訳ではない**。正本データは公開リポジトリに存在せず、ファイルが添付または許可された原本保管場所が準備されるまでは、凍結テンプレ準拠のPPTX出力を停止する。
