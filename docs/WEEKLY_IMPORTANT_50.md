# ECLIPSE — 重要候補約50件への選抜（実装契約・2026-10-10）

## 目的と位置付け

週報作成AIに渡す**最終的な深掘り調査候補（L3）**を約50件に絞る。**本文作成・実際の掲載決定はしない**。全件保存L1、126候補に該当した全CVEを確保するL2、危険度順のL3約50件は別々に扱う。
元のL1（週のCVE全候補）は無変更でZIPに丸ごと内包し、監査用decision_ledger.jsonlには全CVEと選定・非選定理由を残す。L1の取りこぼしや偽の「週次網羅完了」宣言は拒否する。

## 選定順位（3本柱）

1. **新規CISA KEV追加：全件確定**。週間の`CISA_KEV_DATE_ADDED_IN_WINDOW`があり、公式CISA KEV presentで、CVEがPUBLISHEDのみ。古い既存KEVはこの無条件枠に紛れ込ませない。
2. **承認済み126候補のベンダー：L2への全件登録確定**。CVE CNA原本の`affected.vendor`が承認済み126行のベンダー名・明示aliasに一致する場合のみ確定。曖昧な部分一致やベンダーのHTMLに偶然登場したCVEへのリンクでは確定しない。CNA名が不完全なら取りこぼしの可能性を品質フラグで提示。
3. **その他：新規公開・危険度でL3調査候補を選抜**。既存KEVの掲載だけではL3に繰り返し入れない。対象週の新規公開を必須とし、CNA CVSS・旧EPSS・126ベンダー該当の事実を使って順序を決める。L2内部の従来の注意順スコア（過去KEV +70等）は保存するが、**L3の選抜には使用しない**。

**重要：126ベンダーのCVEをすべて週報本文に載せることと、50件に絞ることは両立しない。** 実際の固定週データでは新規KEVが6件、126候補のベンダー名とCNA原本で一致した新規KEV以外のCVEが3,015件、合計3,021件となった。この3,021件はL2の**評価対象として必ず保持**し、上限による削除は行わない。

L3（新規KEV＋危険度上位）は独立して約50件を生成。新規KEVは絶対に保持し、その他は既存KEV・保存時点のEPSS・CNA CVSSでリスク順に並べる。126ベンダー該当には順位の控えめな加点（+15）を付けるが、ベンダー名だけでL3には載せない。危険度しきい値55未満はL3選抜しない。新規KEVだけで50件を超える例外週は超過を明示し、その全件を保持する。対策製品・ベンダー公告ごとの統合は後工程で扱う。

## 承認済み126候補の名簿 — 2026-10-10 取込済み

正式な元ファイル `ECLIPSE_標準監視ソース調査_126候補_20261010.xlsx`（シート `監視プリセット候補`）を、ChatGPT Libraryの**読取可能な解析済みシート内容**から、`config/important_vendor_126.json` に全126行を移植した。元XLSXそのものの生バイトは認可された取り出しが不可だったため、**元XLSXのSHA-256照合はしていない**（名簿内でもその限界を記録）。

検証件数は **14カテゴリ・126製品群/カテゴリ行・重複除外表示ベンダー名104・P0 65 / P1 60 / P2 1**。元シートの行ID `01-001`〜`14-126`、表示ベンダー名、対象製品群、優先区分、市場区分、情報源のヒント、カテゴリ背景参照URLを保持する。

**126行は126社でも、126の取得成功ソースでもない**。名簿と実際の公式ソース収集は独立したゲートである。名簿のカテゴリ関連URLも公式セキュリティ公告URLと解釈しない。

`aliases` は現段階で全て空にした。CNAのベンダー表記揺れやブランド・買収後のグループ名の同一性が未検証であり、推測の別名を自動付与して**誤った確定選抜**を起こさないため。反面、一部ベンダーは表記違いで候補から漏れる可能性がある。今後、メーカー公式情報に基づいてaliasと製品粒度の照合を追加する。

別ベンダーに同じaliasを付けると衝突として**異常終了**する。テスト `tests/test_approved_vendor_126.py` で名簿の件数・ID・分類を監査する。

## 使い方

~~~bash
export PYTHONPATH=src
python -m eclipse_l0.weekly_important build \
 --source-weekly-zip /private/ECLIPSE_WEEKLY_EVIDENCE_20261004_20261010.zip \
 --vendor-policy config/important_vendor_126.json \
 --target 50 --min-score 55 \
 --out /private/ECLIPSE_IMPORTANT_50_20261004_20261010.zip
python -m eclipse_l0.weekly_important verify \
 --zip /private/ECLIPSE_IMPORTANT_50_20261004_20261010.zip
~~~

**ZIPメンバー**：
- `source-weekly-evidence.zip`: 既存L1の全件・全根拠ZIP。元ファイルとバイト単位で同一。
- `important_vendor_126.json`: 実行に使用した承認済み名簿の元バイト。
- `important_candidates.jsonl`: **L2**新規KEV・指定126候補ベンダーCVE等の一次評価対象（件数に上限なし）。
- `top50_research_candidates.jsonl`: **L3**新規KEV全件＋**今週新規公開**されたCVEの危険度上位、目標約50件の週報AI向け調査候補（編集決定ではない）。CNA原文も添付。
- `decision_ledger.jsonl`: L1の全件に対する非掲載候補も含む決定証跡。
- `important_index.json`: 件数・重複を除いた枠内内訳・超過・名簿SHA256。
- `important_quality.json`: 未審査データ、最新EPSS日付欠落、週次完全性・ベンダー収集範囲未証明。
- `important_manifest.json`: L1、選抜・名簿・各ファイルのSHA256、再検証パラメータ。

作成後の`verify`は元のL1 ZIPのmanifestとハッシュ・件数を照合し、**L1＋126ベンダー名簿から選抜を独立再計算して全バイト一致**を要求する。非選抜CVEの削除やパラメータ変更を検出する。

## 2026-10-11 修正：古いKEVと単なるCVE更新の過大評価を排除

実データ初回監査により、旧L3の50件がすべて既存KEVに偏り、**今週新規公開されたCVEは1件だけ**だった。原因：旧`risk_signal_score`は古いKEV在籍に+70を与え、`dateUpdated`しか動かなかった脆弱性が今週の新規警戒枠を独占した。

**修正後の3本柱（L2候補母集団は変更しない）：**

- ① 今週新規登録のCISA KEV：無条件にL3追加。登録日だけが「今週の変化」であり、攻撃開始日の意味ではない。
- ② 承認126行（104表示ベンダー）：該当する全CVEはL2で確実に保持。L3は**今週新規公開**のCVEに限り危険度で選抜。ベンダー名一致単独では選ばない。
- ③ その他：同じく**今週新規公開**のCVEで、CNA CVSS 9以上、またはCVSS 7以上＋EPSS・ベンダー等の補助シグナルで適格と認めたものだけを、残り枠で順位付け。

L3の暫定順位ヒューリスティック：`CVSS*10 + 指定126ベンダー一致8 + EPSSスナップショット閾値別(0/6/10/14)`。EPSSの正確な保存日が欠落しているため最新の悪用予測と呼ばない。CVSSのベクトル/バージョンの差異も単純な数値比較からは評価できない。公式の攻撃前提条件・実悪用・修正済みバージョンを確定したとはみなさない。

同じCNA原文のベンダー×製品が大量に並んだときは同製品再登場ごとに暫定優先順位を16点下げる（**表示上の偏り緩和のみ**。CVEを削除/統合せず、同じ技術的原因ともみなさない）。今週の良い候補が足りなければ50件に水増ししない。

**本番の重要更新は、別の根拠が必要：** CVE `dateUpdated`だけでは、修正版追加・緊急対策・単なる表記編集か判定できない。ベンダーV2の`observed`変更もサイト観測/解析器更新であり、発行元が実際に重要改訂した確証ではない。そのため現時点の「更新のみ」は`decision_ledger.jsonl`とL2に保持して、**未レビューの更新候補**として残す。週報L3に自動混入させない。将来、ベンダーの公表改訂日時と改訂内容を検証できた段階でL3の第四の根拠カテゴリを追加できる。

出力 `top50_research_candidates.jsonl` にはCNA原本の英語説明・影響製品/版の原文・公式参照の有無・未確認事項を`original_l1_cve_source_facts`として添付する。元L1 ZIPのハッシュは固定し、再計算によりL3中に**新規KEVと新規公開以外のCVEが存在しない**ことを監査する。

**固定週再検証（2026-10-04〜10 UTC）:** L1=6,355 / L2=3,021は不変。L3は50件、新規KEV6件、新規公開44件、古いKEVのみの繰り返し0件。指定ベンダー一致21件、その他23件（KEVはこの内訳に含まない）。更新日時のみで内容が重要か未確認のCVEは3,685件（L1に保持）。本数50件は編集済み週報の掲載数ではない。

**品質上の制限：** 依然として固定原本のみで週の全情報を漏れなく観測した証明ではない。新規公開の危険度も専門家による実地レビュー未実施であり、攻撃条件、修正版、露出・脆弱性の成立条件は未確認のままにする。
